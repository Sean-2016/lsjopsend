## 1. 背景与目标

### 1.1 背景

视频推荐消费按 **统计日 × 业务 × 视频一级类目** 落日表。运营需要回答：

1. 推荐侧曝光是否转化为点击、播放、点赞（漏斗）
2. 哪个一级类目在抢曝光（类目对比）
3. 曝光 / 点击 / 播放是否同向变化（趋势）
4. 每个类目每天的播放时长、人均、赞藏转明细

导出样例（2026-09-23，`app_id=SZ-002`）只有四条：`video` 曝光 19 / UV 2，`Tycoon` 曝光 1，`通用` 与 `视频` 为 0。正式环境按全量日表出数，不以这四条为限。

### 1.2 目标

- 提供 **T+1 日表** 只读看板，不接实时流。
- 页级筛选：时间预设 + 起止日 + 一级类目 + 业务。
- 一页展示 KPI、漏斗、类目对比、趋势、日明细、口径，不拆子页。
- 字段与数仓表头一一对应；看板 CTR、漏斗转化率为前端/接口派生，须在口径区写明。

### 1.3 非目标

- 不做实时、不做分钟刷新、不做写入。
- 不在本页维护类目（类目维表 `dim.cat_id` / `dim.cat_name` 只读引用）。
- 不做二级类目、内容 ID 下钻（一期停在一级类目日表）。

## 4. 查询条件

无单独「查询」按钮。任一条件 `change` 后立即重算 / 重请求全部模块。

### 4.1 字段一览

| 控件 | 类型 | 必填 | 默认 | 作用 |
| --- | --- | --- | --- | --- |
| 时间预设 | 下拉 | 是 | 近7天 | 写入开始/结束时间 |
| 开始时间 | 日期到日 | 是 | D−6 | 闭区间左端 |
| 结束时间 | 日期到日 | 是 | D（昨天/最新就绪日） | 闭区间右端 |
| 一级类目 | 下拉 | 是 | 全部类目 | 过滤 `category_l1_id` |
| 业务 | 下拉 | 是 | 当前账号默认业务 | 过滤 `app_id` |

时间预设选项与搜索效果看板相同、顺序固定：昨天、近7天、近15天、近30天、`-`。

筛选栏旁固定灰字：`不含当天`。

### 4.2 T+1 与预设换算

与搜索效果看板完全一致：

- 今天 `T`，最新就绪日 `D = T−1`（若接口返回的就绪日更早，用接口值）。
- 日期控件 `max = D`，当天及以后不可选；越界截断为 `D`。
- 开始 `>` 结束：开始改为结束。
- 昨天 = `[D, D]`；近 N 天 = `[D−(N−1), D]`，**必须右端为 D** 才算命中预设。
- 改预设（非 `-`）→ 改日期并查询；选 `-` → 不改日期。
- 改起止 → 精确匹配预设，否则显示 `-`。任意连续 7 天但结束日不是 D，仍为 `-`。

例：今天 2026-09-28，默认近 7 天 = `[2026-09-21, 2026-09-27]`。

区间建议上限 90 个统计日，超限 toast 并拒绝请求。

### 4.3 一级类目

| 值 | 行为 |
| --- | --- |
| 全部类目 | KPI / 漏斗 / 趋势 / 明细含该业务下全部一级类目 |
| 某个 `category_l1_id` | 上述模块只含该类目 |

选项来源：该 `app_id` 在筛选期内（或最近 90 日）出现过的一级类目 + 维表启用类目。展示 `category_l1_name`，值为 `category_l1_id`。同名不同 ID 必须拆开，不要只按名称聚合。

**类目曝光对比图例外**：始终展示该业务在筛选期内 **全部一级类目** 的曝光 PV，不受「一级类目」下拉过滤，便于对比。当前选中的类目可高亮。原型把过滤后的行拿去画柱、未选类目为 0，正式环境不要把未选类目画成 0，应仍用全类目真实曝光。

### 4.4 业务 `app_id`

- 选项：当前用户有权限的业务列表；原型仅 `SZ-002`。
- 必选单业务，不做「全部业务」一期（多业务 UV 去重跨 app 无意义）。
- 切换业务后：重拉类目下拉（类目随业务变），类目重置为「全部类目」，再查询。

## 5. 数仓字段（日表一行 = 一日一业务一一级类目）

粒度主键：`dt + app_id + category_l1_id`。

| 英文字段 | 中文 / 口径（导出表头） | 类型 | 聚合（区间 / 多类目） |
| --- | --- | --- | --- |
| dt | 统计日期 | 日 | 过滤，不求和 |
| app_id | 业务 id | 维 | 过滤 |
| category_l1_id | 视频一级类目 ID（dim.cat_id） | 维 | 过滤 / 分组 |
| category_l1_name | 视频一级类目名称（dim.cat_name） | 维 | 展示；以 ID 为准 |
| exposure_pv | 推荐曝光 PV：`recommend_list_view` 次数 | 次数 | SUM |
| exposure_uv | 推荐曝光 UV；访客键 `COALESCE(uid, device_id)` | 人数 | **区间去重，禁止日 UV 相加** |
| click_pv | 推荐点击 PV：`recommend_list_click` 次数 | 次数 | SUM |
| click_uv | 推荐点击 UV | 人数 | 区间去重 |
| play_item_cnt | 有播放内容数：当日 `video_play` 去重视频数 | 个数 | 区间去重视频；一期若只有日表可 SUM 并标注「日去重之和」 |
| play_pv | 播放 PV：`video_play` 次数 | 次数 | SUM |
| play_uv | 播放 UV，访客键同上 | 人数 | 区间去重 |
| play_dur_sec | 播放总时长（秒） | 秒 | SUM |
| avg_play_dur_per_uv | 人均播放时长（秒）=`play_dur_sec/play_uv`；`play_uv=0` 为空 | 派生 | **禁止 SUM**；用 `SUM(play_dur_sec)/区间 play_uv` 重算 |
| avg_play_cnt_per_uv | 人均观看个数=`play_pv/play_uv`；`play_uv=0` 为空 | 派生 | **禁止 SUM**；用 `SUM(play_pv)/区间 play_uv` 重算 |
| like_pv | 点赞 PV：flag=1 次数 | 次数 | SUM |
| like_uv | 点赞 UV：有效点赞去重访客 | 人数 | 区间去重 |
| collect_pv | 收藏 PV：flag=1 | 次数 | SUM |
| collect_uv | 收藏 UV | 人数 | 区间去重 |
| share_pv | 分享 PV：`video_share` | 次数 | SUM |
| share_uv | 分享 UV | 人数 | 区间去重 |
| ingest_time | 派生入库时间 | 时间 | 不展示或仅明细 tooltip |

一期若数仓只提供日粒度 UV、做不了区间去重：接口必须返回日明细，KPI 的 UV 改为「日 UV 之和（存在重复访客）」并在卡片说明写清；**不得静默当真实区间 UV**。推荐数仓出区间汇总接口。

空值：导出里人均两列在 `play_uv=0` 时为空字符串。前端 / 接口一律当 `null`，展示 `—`，不要当 0。

## 6. 看板派生指标

数仓原表没有 CTR、漏斗转化、互动合计，由查询层计算。

### 6.1 CTR（推荐点击率）

```
CTR = SUM(click_pv) / SUM(exposure_pv)
```

曝光 PV = 0 → `—`，不展示 0% / Infinity。  
明细表每一行用该行 `click_pv / exposure_pv`。  
**不是** 点击 UV / 曝光 UV。

### 6.2 漏斗与层间转化

四层，均为 **PV 次数**，转化相对 **上一层**（不是相对曝光）：

| 层 | 指标 | 展示转化 |
| --- | --- | --- |
| 1 曝光 | exposure_pv | 无 |
| 2 点击 | click_pv | 点击 / 曝光 |
| 3 播放 | play_pv | 播放 / 点击 |
| 4 点赞 | like_pv | 点赞 / 播放 |

上一层为 0：该层转化显示 `—`。  
条长度相对四层中的最大值，不是相对曝光。

漏斗用播放 PV、点赞 PV，不用 UV，避免和次数漏斗混用。

### 6.3 互动 PV

```
interact_pv = like_pv + collect_pv + share_pv
```

KPI 主数值用合计，说明行拆开赞 / 藏 / 转的 PV。

### 6.4 时长展示

- 明细「播放时长」：`play_dur_sec` 格式化为 `XmYs` 或 `Xs`（如 `3m20s`）。
- 人均时长：同样格式；`null` 为 `—`。
- 人均个数：保留 2 位小数。

## 7. KPI 卡片

从左到右 5 张，数值来自当前筛选下的 **汇总**（§5 聚合 + §6 派生）。

| 顺序 | 名称 | 主数值 | 单位 | 下方说明 |
| --- | --- | --- | --- | --- |
| 1 | 推荐曝光 | exposure_pv | PV | UV {exposure_uv} |
| 2 | 推荐点击 | click_pv | PV | CTR {ctr} · UV {click_uv} |
| 3 | 播放 | play_pv | PV | UV {play_uv} · 内容数 {play_item_cnt} |
| 4 | 人均播放时长 | avg_play_dur_per_uv | 无（已含 s/m） | 人均个数 {avg_play_cnt_per_uv} |
| 5 | 互动 PV | interact_pv | 无 | 赞 {like_pv} · 藏 {collect_pv} · 转 {share_pv} |

分母为 0 或人均无法计算：主数值或说明中对应项为 `—`。

## 8. 图表

横轴统计日为筛选闭区间内每一天；缺数日补 0 或断点，日期不要挤掉。>15 天时横轴抽稀，首尾必标。当天不得出现在轴上。

### 8.1 推荐消费漏斗

- 副文案：曝光 PV → 点击 PV → 播放 PV → 点赞 PV · 转化率相对上一层
- 右侧文案：`{次数}`，第 2～4 层追加 ` · {转化率}`
- Hover（可选）：绝对次数 + 转化率
- 数据随时间、类目、业务变化

### 8.2 类目曝光对比

- 横向柱：各 `category_l1_name` 在筛选期内 `SUM(exposure_pv)`
- 排序：曝光倒序（原型按维表顺序；正式按曝光倒序更清晰）
- 值为 0 的类目仍列出，柱宽 0，避免「没数据以为没类目」
- 不受一级类目下拉过滤（§4.3）
- Hover：类目名、曝光 PV、可选曝光 UV

### 8.3 曝光 / 点击 / 播放趋势

- 通栏折线，左轴次数
- 蓝实线：当日 SUM(exposure_pv)
- 橙虚线：当日 SUM(click_pv)
- 绿实线：当日 SUM(play_pv)
- 三条都按日汇总当前筛选（类目 / 业务）
- 图例三项与上面对应
- Hover：日期 + 三指标
- 空区间：模块内「所选时间范围内暂无数据」

## 10. 页脚口径（固定）

与数仓表头 + 看板派生一致：

- **曝光 PV / UV**：recommend_list_view 次数；UV 访客键 = COALESCE(uid, device_id)。
- **点击 PV / UV**：recommend_list_click。
- **有播放内容数**：当日 video_play 去重视频数。
- **播放 PV / UV / 时长**：video_play 次数、去重访客、play_dur_sec 总和。
- **人均播放时长** = play_dur_sec / play_uv；**人均观看个数** = play_pv / play_uv；play_uv=0 为空。
- **点赞 / 收藏**：flag=1 的有效互动 PV/UV；**分享**：video_share。
- **本页 CTR** = 点击 PV ÷ 曝光 PV，查询层计算，非数仓原字段。
- **漏斗转化** = 本层 PV ÷ 上一层 PV。
- 数据 T+1，当天不可查。

若 UV 一期只能日累加，必须在此加一句「多日 UV 为日 UV 之和，存在重复访客」。

## 11. 接口建议

服务端拒绝或截断 `end_date >= 今天`。路径可按网关改名。

### 11.1 筛选项 `GET /api/l1-consume/meta`

Query：`app_id`（可选）

返回：`latest_ready_date`、`apps[]`（id、name）、`categories[]`（id、name，建议按当前 app）

### 11.2 汇总 `GET /api/l1-consume/overview`

Query：`start_date`、`end_date`、`app_id`、`category_l1_id`（空=全部）

返回：

- `kpis`：exposure_pv/uv、click_pv/uv、ctr、play_pv/uv、play_item_cnt、play_dur_sec、avg_play_dur_per_uv、avg_play_cnt_per_uv、like_pv、collect_pv、share_pv、interact_pv
- `funnel[]`：name、pv、conv_from_prev（第一层 null）
- `category_exposure[]`：category_l1_id、name、exposure_pv（**全类目**，忽略 category 筛选）
- `trend[]`：date、exposure_pv、click_pv、play_pv（随类目筛选）

### 11.3 明细 `GET /api/l1-consume/daily`

Query：同上

返回行：§5 日表字段 + 行级 `ctr`。排序：dt 降序、exposure_pv 降序。

分页：类目数 × 天数可能较大，建议 `page_size` 默认 100，或按日期区间一次返回（90 天 × 数十类目可接受）。

### 11.4 时序

打开 / 改筛选：meta（若类目随业务变）+ overview + daily 并行。

## 13. 验收清单

1. 菜单与面包屑为「一级类目消费看板」。
2. 默认近 7 天，结束日 = 昨天（或接口就绪日），不含今天。
3. 日期选不了当天；越界被截断。
4. 预设与起止联动与搜索效果看板一致（含 `-`）。
5. 业务切换重置类目为全部并刷新。
6. 类目筛选影响 KPI、漏斗、趋势、明细；**对比图仍为全类目曝光**。
7. KPI 人均时长 / 人均个数按汇总重算，不是把日均人均相加。
8. play_uv=0 时人均两列和 KPI 人均为 —。
9. CTR = 点击 PV / 曝光 PV；曝光为 0 时为 —。
10. 漏斗四层 PV，转化相对上一层。
11. 趋势三线为日 SUM 曝光 / 点击 / 播放。
12. 明细粒度日 × 业务 × 一级类目，日期倒序、同日曝光倒序。
13. 无「实数」角标；无当天日期行。
14. 页脚口径含 CTR 为派生、T+1。
15. 接口拒绝查询今天。

| --- | --- | --- |
| 除 2026-09-23 外的日期 | 前端演示序列 | 数仓真数 |
| 2026-09-23「实数」角标 | 有 | 无 |
| 多日 UV / 播放内容数 | 日指标相加 | 区间去重（或明确标注日之和） |
| 类目对比 | 随类目下拉过滤，其它类目为 0 | 始终全类目真实曝光 |
| 业务 | 写死 SZ-002 | 权限下业务列表 |
| 类目列表 | 写死 4 个 | 维表 / 出现过的类目 |
| 查询 | 本地过滤 | 接口 |
| 信息条 | 含演示说明 | 只保留 T+1 / 就绪日 |
