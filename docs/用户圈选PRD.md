## 1. 范围

### 1.1 本期交付（P0）

- 标签库：16 条预置标签的查询、编辑描述、启停、引用查看。无新建标签。
- 人群包：创建、编辑、启停、删除、模板、条件、当次请求地区、用户设备、预估、版本。
- 判定服务：按当前标签重算；同一次请求一份标签快照；失败走兜底。
- 策略绑定：金币包、视频会员用户群体、任务受众；以及需开发策略的登记。
- 权益进度：报价、已发放未核销、已核销、实验入组。
- 决策记录：供客服、财务、实验读取。

### 1.2 不在本期

- 运营新建标签、自由脚本、静态用户 ID 文件当人群。
- 推荐排序、自动营销旅程、偏好人群导出。
- 推送发送页、实验配置页。这两类的时间语义和复核规则本期写死，页面后接。
- 把商品 ID、价格、文案写进人群条件。

### 1.3 约束

- 人群存条件，不存用户名单。名单只允许作为估算或发送前的临时结果。
- 调用方只提交用户、场景、策略 ID，不读取标签明细，不自行实现「新用户」。
- 新用户全站一个口径，见 BR-ID-01。
- 合规、风险的优先级不可被运营下调。

## 2. 角色

| 角色 | 职责 |
| --- | --- |
| 运营 | 编辑标签描述；创建和维护人群包；在金币包、视频、任务上选择已启用人群包 |
| 策略 / 开发 | 登记需开发策略的策略 ID、场景、核销方式；不在代码中复制人群条件 |

| 客服 / 财务 | 按决策记录和订单上的规则版本解释价格，不按用户当前人群解释历史订单 |
| 数据 | 按标签时效更新标签；支付、退款、注销实时 |

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 标签 | 用户或设备上的一个事实。阈值不写在标签上 |
| 人群包 | 一组条件 + 版本。回答「他是谁」 |
| 策略 | 某场景命中后给出的商品、价格、内容或动作。回答「给他什么」 |
| 策略绑定 | 策略 ID 引用哪个人群包、用哪种时间语义和核销方式 |
| 闩锁 | 一旦写成「是」不再回写成「否」。空值不是「否」 |
| 标签快照 | 同一次请求内会员、金币及其他调用方读到的同一版标签 |
| 短粘性 | 一次报价在有效期内保持不变 |
| 核销 | 用户实际使用已发放权益（支付、用券、领奖）的时点 |
| 决策记录 | 一次判定的人群版本、策略、原因、报价到期时间 |

## 4. 业务规则

### 4.1 标签

| 编号 | 规则 |
| --- | --- |
| BR-TAG-01 | 第一期只有附录 A 的 16 条标签。禁止另建：曾付费、新用户、老用户、回归用户、免费用户、金币用户、会员用户、注册时长 |
| BR-TAG-02 | 天数、金额、秒数、统计窗口写在人群条件上，不写在标签上 |
| BR-TAG-03 | 闩锁只接受「明确是 / 明确否」。空值、未回放不等于「否」，该条件不命中 |
| BR-TAG-04 | 年龄验证的未知、超时、厂商失败，判定为未通过。成人内容不可售 |
| BR-TAG-05 | 账号状态非「正常」，商品和推送都不出 |
| BR-TAG-06 | 观看时长无有效播放时为 0，不是未知 |
| BR-TAG-07 | 付费金额的产品线必填，无默认值。退款可以把金额减到 0，对应支付闩锁仍为「是」 |
| BR-TAG-08 | 设备核销标签的主体是设备。换游客号不清除。订阅新人档与金币新人档互不影响 |
| BR-TAG-09 | 注册时长、到期距今、首次支付距今、最后活跃距今，用当前时间减去标签时间。比较单位为小时：界面上的 N 日 = N×24 小时，不用自然日 |
| BR-TAG-10 | 当次请求地区不是用户标签。不选地区表示不限地区，但该地区必须可售。选出的地区表示当次请求必须落在这些地区内且可售 |
| BR-TAG-11 | 用户设备不是用户标签。取值只有安卓 android、苹果 ios、Web web、H5 h5。新建默认四项全选，可取消一项或多项。当次请求设备必须属于仍选中的集合。全部取消则没有设备命中。空数组不表示不限设备 |

### 4.2 人群与判定

| 编号 | 规则 |
| --- | --- |
| BR-SEG-01 | 每次请求按当前标签重算。人不会因为曾经命中而继续属于该人群包 |
| BR-SEG-02 | 包含区默认同时满足（AND）。满足任意（OR）仅作用于包含区。排除区命中任意一条即不进包 |
| BR-SEG-03 | 同一标签在同一个人群包的包含区与排除区合计只能出现一次 |
| BR-SEG-04 | 判定服务强制执行，与运营是否把它们写进包含区无关：年龄验证 = 通过；账号状态 = 正常；当次请求地区可售 |
| BR-SEG-05 | 停用标签仍被人群包引用时，该条件视为不成立，人群包其余条件继续计算。启用前须二次确认 |
| BR-SEG-06 | 计算超时、标签缺失、服务失败：走该场景兜底，原因码 = 兜底。禁止把失败当成命中 |
| BR-SEG-07 | 未知支付闩锁时，不出新人价、不出「明确否」才能享受的优惠 |
| BR-SEG-08 | 同一次请求只读一份标签快照。会员与金币的快照版本必须相同 |
| BR-SEG-09 | 改已发布规则生成新版本。旧版本只读，供历史订单和决策记录解释。回滚在下一次请求生效，不洗用户列表 |
| BR-SEG-10 | 人群规则必须有结束时间。到点停止被新请求命中。已产生的订单和未过期报价按原版本处理到各自到期 |
| BR-SEG-11 | 估算人数为 0，或超过发布前设定的上限时，禁止发布 |
| BR-SEG-12 | 包含区标签可以为空。当次请求地区、用户设备可以单独或一起构成人群包。未选择人群包不等于全部用户；要覆盖全部用户时引用 `pack_all`。该包仍执行 BR-SEG-04 |

### 4.3 身份

| 编号 | 规则 |
| --- | --- |
| BR-ID-01 | 新用户 = 身份类型为已注册，且从未成功支付（订阅闩锁与金币闩锁均为明确否），且注册不满 168 小时。缺一不可 |
| BR-ID-02 | 在订 = 订阅状态为在订，且权益到期时间大于当前时间，且最近一笔不是未完成退款。在订只看续费和加购，不看首购、新人、回归 |
| BR-ID-03 | 首充、首次订阅、首次购币按账号。退款不把闩锁重置为否 |
| BR-ID-04 | 游客用游客 ID，只允许游客策略。不预支注册后的 168 小时 |
| BR-ID-05 | 游客绑定已有账号后，立即改用该账号重算。该账号不是新人。支付闩锁以账号为准 |
| BR-ID-06 | 注销后重注册：支付标识或设备风险能对上时，标为非纯新。对不上时也不给予新人优惠 |
| BR-ID-07 | 人群主键是账号。设备号只用于风险和设备核销标签 |
| BR-ID-08 | 退款：退出在订，进入曾发生成功支付的状态，不进入从未付费 |
| BR-ID-09 | 全额退款后，付费金额可为 0，支付闩锁保持「是」 |

### 4.4 冲突顺序

命中多条策略时按下列顺序，高优先级直接结束。业务只能调整第 5 层内部档位。

| 顺序 | 层 | 胜出结果 |
| --- | --- | --- |
| 1 | 合规不可售、不可见 | 不可买。不再看折扣 |
| 2 | 风险、羊毛 | 只留全价或不可买。不参加新人、回归、挽留 |
| 3 | 当前权益 | 在订走续费和加购 |
| 4 | 进行中的实验 | 实验价格盖过常规折扣，盖不过 1～3 |
| 5 | 生命周期优惠 | 新人、回归、挽留同一互斥组，取优先级数字最小的一档 |
| 6 | 默认 | 全价或该场景登记的默认内容 |

### 4.5 时间语义

每个策略绑定只能登记一种。

| 语义 | 适用 | 规则 |
| --- | --- | --- |
| 请求时判定 | 收银台、付费墙、领券、推荐、会员包、金币包 | 每次请求重算。支付成功、退款、注销、权益到期，下一次请求即变 |
| 短粘性 | 同一次收银台报价 | 默认 30 分钟，或跟随会话，取先到者。支付完成、会话结束、用户变为在订、命中合规或风险时，报价立即失效 |
| 发出前复核 | 推送、召回 | 允许提前估算人数。发送前剔除已付费、已退订、已注销、频控已满、风险升高、账号非正常。提前名单不是资格 |
| 实验快照 | 实验入组 | 首次曝光入组。周期内不因变成付费用户而挪组 |
| 订单快照 | 已支付订单 | 订单写入当时的人群版本、策略 ID、原因码。财务和客服认这笔记录 |

### 4.6 权益进度

人群退出只影响下一次判定。未完成权益按下表处理。

| 进度 | 身份变化或退出人群之后 |
| --- | --- |
| 未展示、未发放 | 无待处理权益。下次请求按新身份 |
| 已报价、未下单 | 短粘性。失效后不把该报价转移到新身份 |
| 已发放、未核销 | 核销时再判一次进入条件（含 BR-SEG-04）。不满足则权益失效。不转移到新人群，不与新身份的优惠叠加 |
| 已核销，或实验已入组 | 保持订单快照或实验快照。出人群不改这一笔 |

补充：

| 编号 | 规则 |
| --- | --- |
| BR-BEN-01 | 合规不可售、风险限制，使未报价、已报价、已发放未核销的权益失效 |
| BR-BEN-02 | 已支付订单只走退款流程，不因人群重算改价 |
| BR-BEN-03 | 默认核销方式是「核销时重判」。只有策略绑定显式选择「发放即锁定」时，未核销权益才保留到其自身过期时间 |
| BR-BEN-04 | 「发放即锁定」仍然被 BR-BEN-01 打破 |
| BR-BEN-05 | 回归折扣「打开 App 一次不退出」只保证展示中的商品与已展示的券一致，不表示身份变成在订后券仍可核销 |

### 4.7 策略绑定

| 编号 | 规则 |
| --- | --- |
| BR-BIND-01 | 策略只保存人群包 ID 和规则版本，不复制条件 |
| BR-BIND-02 | 可配置策略：金币包、视频会员用户群体、任务受众。在各自页面选择人群包 |
| BR-BIND-03 | 需开发策略：代码只实现动作。上线前登记绑定。登记后人群包页面可见，即使动作还不能在后台配置 |
| BR-BIND-04 | 选择器只列出已启用人群包，以及当前对象已经选中的已停用包。已停用包不能被新业务新选。已有绑定继续生效，直到解绑 |
| BR-BIND-05 | 删除人群包前，绑定数量必须为 0 |
| BR-BIND-06 | 同一场景多个策略同时命中时，执行第 4.4 节顺序，不在人群包上再排序 |
| BR-BIND-07 | 禁止两个场景各自定义新用户。都引用符合 BR-ID-01 的人群包版本 |

### 4.8 标签时效

| 时效 | 标签 |
| --- | --- |
| 事件后秒级 | 注册、支付成功、续费、退款、到期、注销、退订、年龄验证、地区、账号状态、订阅状态、支付闩锁、设备核销 |
| 分钟级 | 最后活跃、正在看的内容、金币余额 |
| 小时或天 | 观看时长的滚动窗口、付费金额的滚动窗口 |
| 请求时计算 | 距今天数、168 小时窗口、地区可售。不靠离线任务把人移出人群 |

条件区文案：

- 标签不是必填。只选当次请求地区或用户设备也可以保存。年龄验证通过、账号状态正常由判定服务强制执行。
- 模板来源是附录 B 的 5 条系统预置，下拉只显示名称。先选模板，再点「套用模板」。套用替换包含区、清空排除区、包含关系改为同时满足；说明为空时写入模板说明，已有说明不覆盖。名称、当次请求地区、用户设备不变。包含区或排除区已有标签时先确认，取消则不变。套用后仍须点保存才写入列表。人群包不记录模板 key，之后改模板定义不回写已保存的包。
- 当次请求地区不是用户标签。不选表示不限地区。选出的地区表示当次请求须在这些地区且可售。
- 用户设备不是用户标签。默认全选，可取消一项或多项。当次请求须来自仍选中的端。
- 排除区：命中任一标签的用户不进包。
- 停用后：已经引用该包的业务可继续使用；新业务不能再引用已停用的人群包。
- 列表中「已停用」为红色底标签。创建者筛选项来自当前人群包的创建者，去重。重置同时清空搜索、状态和创建者。

## 7. 判定接口

### 7.1 判定

`POST /segment/decide`

请求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| userId | 是 | 注册用户传账号 ID；游客传游客 ID |
| deviceId | 否 | 仅设备核销和风险使用 |
| scene | 是 | 场景编码 |
| strategyId | 是 | 策略 ID |
| requestRegion | 是 | 当次请求地区，ISO 二字码 |
| requestDevice | 是 | `android` / `ios` / `web` / `h5` |
| quotedDecisionId | 否 | 短粘性期内回传，用于认同一报价 |

响应：

| 字段 | 说明 |
| --- | --- |
| decisionId | 决策记录 ID |
| packId | 命中的人群包。兜底时为空 |
| packVersion | 规则版本 |
| strategyId | 胜出策略 |
| reasonCode | `hit` / `compliance` / `risk` / `mutex` / `fallback` |
| snapshotVersion | 本次标签快照 |
| quoteExpireAt | 短粘性到期时间。非短粘性为空 |
| sellable | 是否可售 |

超时与 5xx 由调用方按该场景已登记的兜底策略执行，并记 `fallback`。调用方不得把超时当成命中。

### 7.2 核销

`POST /segment/redeem`

请求：`userId`、`benefitId`、`decisionId`、`scene`。

响应：`allowed`、`reasonCode`。`allowed = false` 时权益状态改为已失效。

### 7.3 发送前复核

`POST /segment/presend-check`

请求：`userId` 列表、`strategyId`。

响应：每个用户 `send` 为 true 或 false，以及剔除原因。

### 7.4 一致性

一次用户请求内，不论会员、金币调用几次 `/segment/decide`，`snapshotVersion` 必须相同。支付成功、退款、注销写入后，下一次请求使用新快照。

## 9. 预置人群包

判定时另加 BR-SEG-04。下表是包含区，模式均为 AND。

| 人群包 | id | 编号 | 创建者 |
| --- | --- | --- | --- |
| 未付费新人 | pack_unpaid | QP0001 | 产品阿陈 |
| 只买过金币 | pack_new_day | QP0002 | 运营小王 |
| 只订阅过 | pack_sub_only | QP0003 | 运营小王 |
| 订阅已过期的回归 | pack_sub_return | QP0004 | 产品阿陈 |
| 试看较深仍未订阅 | pack_trial_deep | QP0005 | 运营小王 |
| 全部用户 | pack_all | QP0006 | 系统 |

### 9.1 未付费新人 `pack_unpaid`

| 标签 | 条件 |
| --- | --- |
| 年龄验证 | 等于通过 |
| 账号状态 | 等于正常 |
| 身份类型 | 等于已注册 |
| 注册时间 | 注册时长不超过 7×24 小时 |
| 发生过成功订阅支付 | 明确否 |
| 发生过成功金币支付 | 明确否 |
| 设备已核销新人订阅 | 明确否 |
| 设备已核销新人金币 | 明确否 |

退出：任一支付成功、满 168 小时、命中风险或合规，立即退出。再入：不允许。核销：`reeval`。订阅商品可去掉金币设备条件，金币商品可去掉订阅设备条件，须另存为新版本，不改本包 ID 的版本 1 语义。调用方通过新人群包引用自己的设备条件。

### 9.2 只买过金币 `pack_new_day`

金币闩锁 = 是，订阅闩锁 = 明确否，订阅状态 = 无，外加两条强制合规条件。

退出：订阅支付成功立即退出。核销：`reeval`。用途是购币用户的首订优惠，不是新人价。

### 9.3 只订阅过 `pack_sub_only`

订阅闩锁 = 是，金币闩锁 = 明确否，外加两条强制合规条件。

退出：购币成功立即退出。核销：`reeval`。

### 9.4 订阅已过期的回归 `pack_sub_return`

订阅状态 = 过期，到期距今超过 7×24 小时，最后活跃距今超过 7×24 小时，外加两条强制合规条件。

退出：重新订阅立即退出，或窗口结束。窗口内再次打开不延长 7 日，也不因此退出。核销：`reeval`。变成在订后，已发放未核销的回归券失效。

### 9.5 试看较深仍未订阅 `pack_trial_deep`

订阅状态 = 无，订阅闩锁 = 明确否，观看时长范围 = 试看、窗口 = 累计、大于 180 秒，外加两条强制合规条件。

改阈值只发布新版本，不新建标签。核销：`reeval`。

### 9.6 全部用户 `pack_all`

保底人群。包含区无标签，当次请求地区不限，用户设备为安卓、苹果、Web、H5。编号 QP0006，创建者「系统」，默认启用。

命中条件只有 BR-SEG-04：年龄验证 = 通过，账号状态 = 正常，当次请求地区可售。策略要覆盖全部用户时引用本包。未选择人群包不表示全部用户。

## 10. 标签条件控件

| kind | 界面 | 校验 |
| --- | --- | --- |
| enum | 等于 + 单选 | 必选一个合法值 |
| latch | 明确是 / 明确否 | 必选。无「未知」选项 |
| time | 文案（注册时长、到期距今、首次订阅距今、首次购币距今、最后活跃距今）+ 不超过/超过 + 整数日 | 日为大于 0 的整数。N 日 = N×24 小时 |
| balance | 比较符 + 个数；区间时两个数 | 可用余额，整数 ≥ 0 |
| watch | 试看/正片/全部 + 窗口 + 比较 + 秒 | 范围和窗口必填 |
| pay | 产品线 + 窗口 + 比较 + 元 | 产品线必填，无默认 |

窗口：近 24 小时、近 7 日、近 30 日、累计、最近 N 日。

选择标签弹窗按分组展示：账号、订阅与金币、活跃与度量。搜索名称或描述。

## 15. 附录 B：模板初始条件

模板只有下表 5 条。由系统预置，不由运营创建，也不从已保存人群包生成。新建和编辑人群包时，下拉「选择圈选模板」只列出这 5 个名称。

套用时把下表条件写入包含区，模式改为 AND，排除区清空。每条模板都带年龄验证 = 通过、账号状态 = 正常。运营可在保存前删除这些展示条件或设备条件；删掉后 BR-SEG-04 仍执行。套用不改人群包名称、当次请求地区和用户设备。说明仅在原来为空时写入模板说明。套用不保存人群包，也不把模板 key 记到人群包上。

| key | 名称 | 除强制展示的年龄验证、账号状态外 |
| --- | --- | --- |
| new_unpaid | 未付费新人 | 已注册；注册时长不超过 7 日；两个支付闩锁明确否；两个设备闩锁明确否 |
| coin_only | 只买过金币 | 金币闩锁是；订阅闩锁否；订阅状态无 |
| sub_only | 只订阅过 | 订阅闩锁是；金币闩锁否 |
| sub_return | 订阅已过期的回归 | 订阅状态过期；到期距今超过 7 日；最后活跃距今超过 7 日 |
| trial_deep | 试看较深仍未订阅 | 订阅状态无；订阅闩锁否；试看累计大于 180 秒 |
